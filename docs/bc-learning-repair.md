# 首轮 BC 学习修复实测（2026-11-27）

自动训练、诊断、游戏评估、检查点和汇总流程已经跑通。学习问题只得到部分改善：
模型能够在示范画面上学到条件动作，两种候选也在实际游戏中切换动作，但本轮所有
游戏射击测试仍没有实际发射子弹，第一阶段游戏能力未达标。

## 本轮范围与实现

- 保留旧模型、20 条训练示范与 6 条验证示范，未修改地图、动作、奖励或成功判定。
- 旧模型的编码器保持兼容；新增 LayerNorm 视觉特征和可选 ReLU 动作头。
- 可选有限平方根逆频率动作权重，只由训练标签计算，并保留“不射击”等负样本。
- 增加开枪/停止/水平转向的召回、精确率和误报，画面历史置换对照及饱和诊断。
- 完整 BC 检查点保存模型、优化器、AMP scaler、随机状态和训练历史；原子写入，
  保留上一代，拒绝配置或数据指纹不一致的恢复。
- [自动实验脚本](automatic-experiments.md) 使用普通子进程，不调用 LLM；有累计时间、
  单阶段时间和尝试次数上限，失败保留日志与轨迹，最终 test 场景不参与迭代。

## 三组固定候选的真实结果

同一 2117 条训练帧、625 条验证帧，batch 128、60 epochs、学习率 3e-4、seed 42、
CUDA AMP。每组使用同一组 dev 种子 200000–200003，各做 4 局路线和 4 局射击测试。
实际游戏使用按未加权验证 NLL 选出的 `best.zip`；`latest.zip` 另存离线诊断。

| 候选 | 验证集开枪命中标签 / 9 | 非开枪帧误报 / 616 | 路线完成 | 射击任务完成 | 游戏实际子弹 |
|---|---:|---:|---:|---:|---:|
| normalized：归一化、原损失 | 0 | 0 | 0/4 | 0/4 | 0 |
| balanced：归一化、有限动作权重 | 3 | 2 | 1/4 | 0/4 | 0 |
| balanced-relu：再换 ReLU 动作头 | 1 | 0 | 1/4 | 0/4 | 0 |

`balanced` 在路线/射击环境分别产生 8/14 种动作，`balanced-relu` 分别产生 8/4 种；
`normalized` 在这批游戏中始终不动。动作种类增加不等于完成能力。
本轮三组实际命中、击杀均为零。每门课只有 4 个开发场景，不能据此宣称稳定成功率。

队列累计子进程耗时约 530.5 秒，三次训练计算分别约 19.75、21.55、20.98 秒。
其余时间包含加载、检查点、诊断、游戏运行等。结束后 GPU 回到约 65 MiB / 0%，
没有继续后台训练，也未追加第 4 种方案。

## 诊断能证明什么

1. 训练管线能够拟合条件动作。独立 tiny-fit 只取 128 个训练样本、300 次更新，
   得到 8 种动作；开枪召回 33/33，但误开枪 16/95；停止召回 69/74，误报 0/54；
   水平转向召回 38/48。打乱画面历史与标签对应后，平均 NLL 上升约 0.3407。
   这是训练集拟合检查，产物有 `test_only` / `diagnostic_only` 标记，不是正式模型。
2. 稀有动作选择和泛化仍弱。`balanced-relu/latest` 对训练集的开枪召回为 42/43，
   验证集仅 3/9；实际游戏没有射击。继续增加 epoch 不能直接证明会改善这个差距。
3. 仅按平均验证 NLL 选模型会遗漏行为差异。`normalized` 的 best 不预测验证开枪，
   latest 能预测其中 2 帧；本轮保留固定选择规则，没有事后悄悄换模型来抬高成绩。
4. 发现一处有限的渲染时序差异：人类按 Enter 前枪械通常已完成举枪，RPC reset
   首帧可能尚未完成。枪械动画使用墙钟，不完全随锁步物理时间推进。最终截图已举枪，
   所以目前没有证据把整局失败归因于这一点；本轮未修改引擎或录制契约。

## 下一步边界

本次自动流程目标完成，实际游戏射击问题尚未解决。后续优先分析“开始不动”和
“接近敌人仍不开枪”的失败片段，区分视觉识别、准星控制、模型选择及示范覆盖问题；
据此设计最少量的定点瞄准/交战纠错示范，并使用包含稀有动作和游戏表现的模型选择指标。
目前不要求用户盲目重复录制整条路线，也不自动开展长训练。新实验需继续保留独立验证
和最终测试边界，不降低成功条件。

## 后续失败定位与已有检查点补测

在用户要求“下一步”后，补测三组已有 `latest.zip`，没有新增训练或第 4 组候选。
使用同样的 4 个 dev 种子、原路线和原射击场景，新增 24 局，耗时约 302.3 秒。

| latest 候选 | 路线完成 | 路线实际子弹（无人） | 射击任务完成 | 射击实际子弹 / 命中 / 击杀 |
|---|---:|---:|---:|---:|
| normalized | 0/4 | 0 | 0/4 | 0 / 0 / 0 |
| balanced | 2/4 | 5 | 0/4 | 5 / 0 / 0 |
| balanced-relu | 1/4 | 0 | 0/4 | 0 / 0 / 0 |

没有将 latest 替换为正式模型。这里只改变了选用的已有检查点；枪械举起/摆动仍存在前文说明的
墙钟时序差异，所以不能把有限次数成绩差异全部归因于检查点。射击行为本身也未通过验收。

只读诊断增加 `scripts/analyze_bc_failures.py`：读取开发轨迹、请求/执行动作、实际子弹计数、
最终终点坐标和人工记录，生成可追溯 JSON。禁止把最终 test 或已参与训练的游戏用作本次失败分析。
辅助坐标只用于报告，不进入模型。静止不再被解释成“撞墙”；桥接器当前路线点距离也不再被误当成最终终点距离。

原 24 局 best 轨迹中，17 局全程无动作；5 局曾移动后长时间停住。一个射击失败回合进入过终点区域，
但敌人仍活着，随后继续跑出终点，没有射击。终点必须同时满足击杀条件，不能修改成功判定掩盖这个失败。

人工训练示范开头共有 139 帧完全无动作，约 6.95 秒；12 条训练射击示范中，
敌人存活时向前移动的帧数是 0，侧移帧是 94。所有开枪位置都在原出生区域附近。
这说明前进后的活敌交战状态没有被覆盖，不代表旧示范无效。

对 179 个真实关键帧使用正确的四帧历史，只读比较六个检查点：`balanced/latest`
能复现训练集全部 43 个开枪标签，但验证集仅 3/9；在 6 条验证示范首次应动作的画面上，
仍有 3 条输出完全无动作。其余候选在相同首次动作检查上也存在等待倾向。
起步等待标签可能形成静止循环，但尚未通过单变量实验证明因果；不能声称已经修复。

原正式评估配置、原示范和模型均保留。实验完成时新增代码与文档先留在本地；随后用户授权
