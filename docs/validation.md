这些结果证明机制和数据流可用。集成控制器读取世界坐标来检查环境，**不是学习模型，也不是真人示范**。普通 BC 拒绝 `script_test`；只有显式 `--allow-test-data` 才用于工具检查，产出的模型和评估均标记 `test_only`。2 个 epoch 的离线损失下降、短训和零差异回放都不是自主游戏能力证据。

短 PPO 检查使用与正式任务控制契约兼容的临时 12 步时限，以验证结束、重置和存档；其开发评估成功率为 0。正式任务仍为 1200 步 / 60 模拟秒，不是这个短测试时限。

同一临时配置的实时模型检查中，模拟/墙钟比约 0.40，记录到约 80 ms 丢时和 1 次输入过期释放。它验证报告能如实拒绝慢速运行，不是 CPU 推理性能基准，也没有达到“流畅游玩”。实际性能需要在目标硬件上运行足够长的完整任务，包含渲染和推理的共同负载。

### 复现机制检查

先按 README 完成引擎、地图和依赖安装。在已有显示环境时：

```bash
python -m pytest -q
python scripts/validate_stage1.py
```

无显示环境时：

```bash
LIBGL_ALWAYS_SOFTWARE=1 xvfb-run -a .venv/bin/python \
  scripts/validate_stage1.py
```

生成的配置、截图、脚本测试示范和 `checks.json` 位于 `runs/stage1-validation/`。选择其中一个 `pipeline-data/episode-…` 后，可用 `valorant-lab replay` 检查同种子动作重放。脚本使用特权诊断检查机制，不应当作模型部署入口。
