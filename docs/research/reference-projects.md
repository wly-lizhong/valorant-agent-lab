# CS:GO、游戏智能体与具身智能参考

核查：2026-11-25。返回[研究目录](README.md)。本文件区分作者报告、本项目推论和未运行的候选工程；未在本机复现下述模型，不复制其性能结论作为本项目指标。

## 1. 如何比较

比较对象必须同时写明：策略看到什么、输出什么、任务多大、训练数据从哪里来、延迟测的是什么。模型名称相似或演示流畅，并不能说明可直接迁移。

| 参考 | 输入 / 输出的关键特点 | 本项目优先借鉴 | 不直接迁移的部分 |
|---|---|---|---|
| CS:GO Behavioural Cloning | 像素驱动控制；采集与标签处理还使用元数据 | 示范采集—清洗—训练—闭环检查 | 旧 CS:GO 接口、权重与特定数据规模 |
| MLMove / CSKnow | 结构化玩家状态，学习移动；规则处理瞄准/射击 | 团队移动评估、学习与规则分工 | 全局状态输入、低延迟数字、职业水平表述 |
| Sample Factory / ViZDoom | FPS 环境中的并行采样、循环策略及评估示例 | 实验组织与吞吐诊断 | 不同引擎的运行速度和任务参数 |
| ACT / ALOHA | 多视角图像和本体状态到动作序列 | 同步示范、短序列协调 | 机械臂状态、长动作块和成功率 |
| Diffusion Policy | 条件动作分布及滚动执行 | 多种合理动作的建模思路 | 首版推理复杂度与机器人结果 |
| Physical Intelligence RTC | 推理与执行重叠，处理动作块衔接 | 世界不停、动作时效和连续性 | 直接照搬其 VLA、块长及延迟容忍度 |
| OpenVLA / Isaac GR00T | 通用机器人视觉、任务与状态/动作适配 | 数据契约、跨任务接口、评估层次 | 现成权重直接控制 FPS 的假设 |

## 2. 游戏与模仿学习证据

### F01 — Counter-Strike Deathmatch with Large-Scale Behavioural Cloning

来源：[论文 v2](https://arxiv.org/abs/2104.04258v2)、[作者仓库](https://github.com/TeaPearce/Counter-Strike_Behavioural_Cloning)。Tim Pearce、Jun Zhu；2021 预印本，CoG 2022。读取范围：论文摘要、作者 README 与工作流说明。

作者报告像素输入的 CS:GO 死斗智能体，使用大规模较噪声数据和较小高质量示范集。仓库公开采集、标签推断、清洗、训练和运行流程。**策略像素输入不等于数据采集完全没有其他状态**：README 的元数据处理不能被描述成只拿普通视频就自然得到可靠键鼠标签。

本项目借鉴：把示范质量、动作标签对齐和闭环运行视为同一条工程链。优先直接记录已执行输入，减少事后猜标签。其结果不证明基础爆破回合、VALORANT 迁移或低配部署已经解决；本轮没有复现旧运行环境。

### F02 — MLMove / CSKnow

来源：[论文 v1，2024-08-25](https://arxiv.org/html/2408.13934v1)、[作者项目入口](https://mlmove.github.io)。重点读取正文 3、4、5、6 节；项目入口由论文提供。

工作针对 Dust2 / Retakes，学习移动并用规则模块处理瞄准与射击；输入含玩家位置等结构化状态。作者报告 5.4M 参数、单个 Xeon 核心约 8 ms 查询、每 125 ms 更新移动；摘要中的约 0.5 ms 是按游戏 tick 摊销成本。它不是“RGB 到全部键鼠动作只需 0.5 ms”的系统。

借鉴其任务缩小、移动/执行分工及位置分布、存活与团队行为评价。我们采用玩家观察约束，不能照用其输入；参考延迟应保留硬件、调用周期和功能范围。

### F03 — Sample Factory 的 ViZDoom 集成

来源：[官方集成文档](https://www.samplefactory.dev/09-environment-integrations/vizdoom/)。读取范围：安装、实验、APPO/RNN 配置和训练/观察入口。

可学习并行实验、策略记忆、训练和演示分开运行的方法。示例工作进程数和数十亿步训练配置服务于相应 Doom 实验，不是 CA-VAL-AIM 的默认配置。先定位本引擎的渲染、图像传输和物理瓶颈，再决定是否迁移框架；现有 PPO 保留为基线。

### T01 — DAgger：学习者访问状态上的纠错

来源：[Ross、Gordon、Bagnell，AISTATS 2011](https://proceedings.mlr.press/v15/ross11a.html)。读取范围：作者论文页面与摘要。

关键问题是策略动作会改变后续观察分布，训练时只看专家的成功轨迹容易累积偏差。本项目据此安排模型自主运行、收集偏离与恢复状态、补充指导，再重新训练。具体纠错流程需要实现；给任意失败视频补一个标签，并不自动等于完整复现 DAgger。

### T02 — Recurrent PPO

来源：[SB3-Contrib 官方文档](https://sb3-contrib.readthedocs.io/en/master/modules/ppo_recurrent.html)。核查页面展示 2.9.2。存在 CnnLstmPolicy，支持 MultiDiscrete 动作；预测时需要正确传递记忆和 episode_start。

它提供视觉加记忆的候选组件，不自动完成示范预训练、权重迁移、动作头或实时调度。项目当前是普通 CnnPolicy 加帧堆叠；引入循环策略必须保留重置、序列切分与导出一致性检查。

### T03 — Asymmetric Actor Critic

来源：[Pinto 等，2017](https://arxiv.org/abs/1710.06542)。读取范围：论文摘要。作者使用图像观察的 actor 与全状态 critic，原始观察包括 RGBD，并结合域随机化进行机器人实验。

可参考训练期价值评估利用模拟器状态、运行策略只用允许观察的分离方式。它不意味着允许把 critic 状态串进共享输入，也不证明纯 RGB FPS 已解决。首版先把状态用于奖励和诊断；非对称 critic 是后续候选。

## 3. 具身智能证据

### R01 — ACT / ALOHA

来源：[作者项目页，RSS 2023](https://tonyzhaozh.github.io/aloha/)。读取范围：摘要、算法与观察说明；未逐段观看演示视频。

作者用遥操作示范学习双臂任务，ACT 从多相机与关节状态预测动作块。借鉴同步采集和连续动作协调。机器人本体状态不等于 FPS 玩家输入；页面中的少量示范成功案例不能推算游戏训练时长。若尝试动作块，应测试短、可打断的执行窗口。

### R02 — Diffusion Policy

来源：[作者项目页，RSS 2023 / IJRR 2024](https://diffusion-policy.cs.columbia.edu/)。读取范围：方法介绍、滚动执行及实验入口。

它对条件动作分布进行建模，通过去噪产生动作序列，并采用滚动执行。对“同一观察存在多种合理路线/动作”的问题有启发；但额外采样计算及 FPS 响应要求需实测。首版使用较简单的策略，只有确定动作多模态是瓶颈后再比较。

### R03 — Physical Intelligence：Real-Time Action Chunking

来源：[机构原文](https://www.pi.website/research/real_time_chunking)，初发 2025-06-09，页面含后续更新。读取范围：全文方法说明；未运行其代码。

文章指出推理期间执行仍在继续，新旧动作块必须兼顾已经执行的部分与新观察。单纯分块或平滑不能保证连续有效。本项目借鉴的是异步执行、时间戳和衔接问题意识；不把其 diffusion/flow VLA 算法直接当作现有 CNN 控制器实现，也不照搬机器人块长或延迟数字。

### R04 — OpenVLA

来源：[作者项目页](https://openvla.github.io/)。读取范围：模型、数据与适配实验说明。

项目展示视觉—语言—动作模型及跨机器人适配，基础模型为 7B。它证明已有公开的通用机器人策略工程，但动作编码、训练分布和硬件与 FPS 不同。可借鉴任务/动作接口和微调评估流程；目前没有理由把大 VLA 设为本项目基础移动射击的必需组件。

### R05 — NVIDIA Isaac GR00T

来源：[NVIDIA 官方仓库](https://github.com/NVIDIA/Isaac-GR00T)。核查当日 README 为 N1.7；读取范围：模型定位、数据格式、适配与部署流程。

仓库显式组织 video/state/action、modality 配置、任务与 embodiment，并区分离线评估和实际执行。借鉴这种输入输出契约和验证层次。首版不会接入其现成权重；机器人状态和动作字段需要重新定义，公开模型也不代表自动具备游戏知识。未来采用时重新核查版本和硬件要求。

## 4. 实时运行与后期部署参考

### E01 — Godot 物理插值与相机

来源：[官方高级物理插值说明](https://docs.godotengine.org/en/stable/tutorials/physics/interpolation/advanced_physics_interpolation.html)。相机与物理插值需分别考虑，视觉平滑不等于输入新鲜。本项目应测相机更新、画面形成与动作应用时刻，避免用平滑隐藏旧决策。

### E02 — ONNX Runtime

来源：[量化](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html)、[线程管理](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)。量化校准、算子支持、线程数与精度/速度均需对目标设备实测。计划先保存可靠浮点基线，后期再比较压缩、线程和执行后端；不把文件变小视为实时达标。

## 5. 从参考到本项目的可执行结论

| 结论 | 主要依据 | 本项目行动 | 必须自己补的证据 |
|---|---|---|---|
| 示范先解决基本动作，再补自主运行偏差 | F01、T01、R01 | 录制与回放、BC、纠错样本 | 同步质量、闭环成功率和恢复能力 |
| 学习策略与明确规则可分工 | F02 | 规则切换任务，视觉策略处理操作 | 规则不读隐藏状态；比较规则对照与学习策略 |
| 连续运行是系统问题 | R03、E01 | 独立时钟、最新观察、动作有效期 | 完整链路延迟和原速录像 |
| 模拟器状态可服务训练，但不进入执行策略 | T03 | 奖励/诊断与观察分层 | 输入审计与遮挡测试 |
| 小型视觉记忆策略先作基线 | T02；本项目工程选择 | 帧堆叠对照、CNN+LSTM 候选 | 改善是否来自记忆、是否引入动作惯性 |
| 通用机器人模型先保留为备选 | R02、R04、R05 | 优先定义契约与数据，不先扩大模型 | 有明确瓶颈后再做等预算实验 |

这些结论是跨来源综合后的设计选择，没有一篇来源验证过本项目的整套组合。下一步实验与失败时的替代路线见[数据、训练与评估规范](data-training-evaluation.md)及[决策记录](decisions.md)。
