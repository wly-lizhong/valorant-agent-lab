# 人工纠错、替代方案与后续训练路线

更新：2026-11-26。用户已授权第一阶段工程实现，并明确本地是无 GPU 低配开发电脑。本文区分采用的方法、当前代码和仍需对照实验的假设；可执行命令以[使用手册](../stage1-guide.md)为准，默认硬件分工见[云端工作流](../cloud-workflow.md)。

## 1. 最终目标决定选择

第一目标是使用玩家信息，连续完成真实地图中的基本任务。允许固定角色、武器、路线和岗位，因此可以用明确的任务约定降低难度。模型大小、是否端到端、是否拥有复杂网页平台都不是验收目标。

主线：正常示范 → 视觉 BC → 独立自主评估 → 自动筛选代表性失败 → 真人补课 → 混合数据重训 → PPO 对照/微调。全过程分别记录工程正确性、学习能力和实时表现。

| 候选路线 | 用途 | 当前取舍 |
| --- | --- | --- |
| 小型视觉策略＋短期历史 | 根据画面连续输出操作 | 已接入 CNN＋4 帧；先建立可测基线 |
| 有限任务规则＋视觉控制 | 固定岗位、交战后恢复职责 | 固定任务已定义；运行策略的分层状态机待实验，不能读取隐藏状态 |
| 图像目标与地标路线 | 减少固定路线的学习负担 | 借鉴 ViNT 思路，尚未接入，先小规模对照 |
| 纯 PPO 从零探索 | 提供对照，或改善已有行为 | 保留入口；优先先有正常示范，避免只靠稀疏奖励找解 |
| 视觉检测＋反馈控制 | 可解释的射击/导航诊断基线 | 待需要时增加，分开报告规则控制器和模型的成绩 |
| 大型 VLA / LLM 每步控制 | 广泛任务理解 | 不作为首版动作路径；高层规划可后续另评估 |
| 完整多人自博弈 | 对抗策略和团队行为 | 基本移动交战可靠、回合规则完整后再考虑 |

“训练时有模拟器”允许自动出题、评分与诊断。后台信息不自动成为部署策略的输入。首版没有使用特权 critic，避免同时引入复杂算法与观察边界问题。

## 2. 对应的学术方法

用户提出的“把失败切成题目，真人给正确操作”属于纠正示范、交互式模仿学习或 learning from interventions 的范畴。具体命名取决于实现，不能只加一个人工按钮就声称复现某算法。

| 方法 | 核心思想 | 本项目如何借鉴与限制 |
| --- | --- | --- |
| [DAgger](https://proceedings.mlr.press/v15/ross11a.html) | 在当前策略实际访问的状态上获得专家动作，并聚合数据 | 自主评估发现失败、追加专家示范；本版从起点重做，未逐状态实现完整 DAgger |
| [HG-DAgger](https://arxiv.org/abs/1810.02890) | 人类决定接管并纠正危险/错误行为 | 可作为未来实时接管参考；本版是异步题目队列 |
| [DART](https://proceedings.mlr.press/v78/laskey17a.html) | 示范时加入经设计的扰动，让专家展示恢复 | 首版起点、朝向与仰角课程受其启发，未实现论文中的噪声优化算法 |
| [HIL-SERL](https://hil-serl.github.io/) | 将示范、人类介入与机器人强化学习组织为系统 | 借鉴工程闭环，不能直接当作现有 PPO 的即插即用扩展 |
| [Reverse Curriculum](https://proceedings.mlr.press/v78/florensa17a.html) | 逐步扩大能够完成任务的起始状态范围 | 后续从接近成功、可恢复的起点逐步扩展；不只反复训练极端失败 |

原始 DAgger 的游戏实验包含 SuperTuxKart 与 Super Mario；HG-DAgger、DART、HIL-SERL 的实验任务也不等于本项目 FPS。这里借鉴方法，未把它们的论文成绩作为本项目承诺。

## 3. 人工时间用在哪里

先采正常行为，避免初始随机策略产生大量无价值题目。随后把资源优先给高频、有影响、可恢复且具有代表性的失败；相似墙角重复案例合并，保留种子与版本。

每张题明确公开目标、失败现象、操作入口、成功条件。系统判断“需要候选补课”，用户不需要守着训练决定何时中断。成功示范只说明数据可用，更新后的模型必须独立复测。

首版题目从整个回合起点重做：可以同时教预防、恢复和继续原任务。完整快照以后单独实现，必须涵盖物理、相机、枪械、Bot、随机、输入与任务状态；只有录像不能恢复现场。循环策略还需重建历史记忆。

缺点与应对：

- 只补失败容易遗忘正常操作：训练中保留正常示范，并回归正常任务。
- 只学卡死后救场可能不懂预防：重做失败前过程，并加入轻微主动扰动。
- 一题可能有多种正确解：不把与某个示范动作不同直接判为错误，以最终任务结果为主。
- 人类反应和串流延迟污染标签：保存浏览器实际看到的帧、输入及执行时间，先验证云端交互链路对齐，再扩大远程采集；仅记录服务器截图时刻不够。
- 有些卡住是接口或物理错误：先证明同一接口能完成，修环境问题后再要求模型学习。
- 反复使用考试题会污染成绩：补课只能来自开发集，新增独立留出变体和完整任务验收。

## 4. 无桌面 Linux 与浏览器方案

2026-11-26 修正默认流程：本地只写代码和通过浏览器操作，游戏渲染、示范采集、训练与评估放在云端。现有桌面采集器是可复用工具，不能假设低配开发电脑能流畅运行它。数据格式继续独立于前端；PPO/评估在具备图形能力的云实例运行，当前尚未实现跨主机采样器。

浏览器入口现已前移到首批人工示范之前，尚未实现。最小方案是独立云端交互实例＋视频流＋相对鼠标/键盘通道，先能领取一个课程并录制正确示范，再接入已有失败题库。优先异步领取题目，实时接管作为额外入口。可以评估 [Selkies](https://docs.selkies.io/latest/components/web-client/) 等串流组件；通用串流能操作不代表标签时序已经满足训练要求。

Godot 4 C# 的[官方 Web 导出限制](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html)意味着当前项目不能直接承诺导出成浏览器游戏。无桌面不等于无渲染；GPU 的 CUDA、图形渲染与视频编码能力要分别检查。先用受控内网或 VPN，公网入口需要鉴权、HTTPS 和适当的连接管理；底层 loopback RPC 不直接对公网暴露。

浏览器前端需记录实际展示的帧号、输入产生与应用时刻、控制权变化；断线和失焦释放按键。时间戳能帮助诊断，不能自动消除网络延迟。人工与模型不能同时争抢输入。

## 5. 固定路线与自动教师

[ViNT](https://general-navigation-models.github.io/vint/) 使用当前/历史图像、目标图像与拓扑规划进行机器人导航。可尝试在真人走过的路线保存自然地标画面，遇敌后继续寻找下一个地标；暂不假设其机器人权重能直接适配 FPS。对照重点是偏离路线、相似走廊和交战转头后的恢复。

[微软视觉游戏 BC 项目](https://github.com/microsoft/imitation_learning_in_modern_video_games)支持 CS:GO/Minecraft，提供视觉编码器与动作策略结构。可比较小 CNN 与预训练视觉编码器；后者离线缓存特征能减少训练重复计算，但部署时仍要计算视觉特征。

自动教师必须执行同样的动作接口。上游 [TacticalDev.cs](https://github.com/Pyromesis/CA-VAL-AIM/blob/v2.11.0/CaValAim/src/Modes/TacticalDev.cs) 中部分自动演示直接传送位置、赋值视角，不能原样作为正常键鼠数据。本版机制检查脚本使用世界坐标来检查路线和枪械，明确标为测试数据；它不代表玩家信息条件下的教师或已学会策略。

训练时可利用模拟器真值做场景生成、奖励和可见目标监督。后续的 [Asymmetric Actor-Critic](https://arxiv.org/abs/1710.06542) 也是候选，但部分可观测任务的 critic 设计需注意[相关偏差研究](https://arxiv.org/abs/2105.11674)。首版不以此作为前置依赖。

## 6. 接下来按什么证据推进

1. 机制与云端交互：保留已通过的受控机制检查，在目标云实例核验 GPU 渲染；补齐浏览器操作、失焦/断线释放与帧/动作对齐。
2. 首批真人数据：通过低配本地浏览器操作云端训练器，先试采、重放与人工检查，再训练 BC；检查模型是否学到正常动作，而不是高比例输出无操作。
3. 自动补课：对比补课前后相同开发题，以及未见变体和正常任务，确认改善没有以遗忘为代价。
4. PPO 对照：同等环境预算比较 BC、BC＋补课、BC 初始化 PPO；不只看总奖励。
5. 实时：在正常游戏时间下检查整段成功、动作连续性、推理和采样延迟；CPU/低配部署优化随后推进。
6. 扩展：1B 跟队守点，再到 1C 爆破回合；技能、声音及复杂多人学习继续后置。
