# 决策、取舍与待验证事项

更新：2026-11-25。返回[研究目录](README.md)。这里记录技术依据、取舍与验证条件。

## 1. 采用的方向

| 决策 | 原因 | 代价 / 限制 | 何时重新评估 |
|---|---|---|---|
| 保留 CA-VAL-AIM 与 Lotus | 已能加载地图、控制、重置和训练 | 物理、HUD、回合机制与目标游戏仍有差异 | 必要机制无法实现或校准成本失控 |
| 首版固定角色、武器与路线范围 | 减少同时学习的变量，失败易定位 | 不能直接宣称跨地图和多武器泛化 | 单图基础闭环稳定后 |
| 以玩家可获得信息运行 | 符合目标，也便于以后更换控制后端 | 感知误差和未知状态必须显式处理 | 这是项目约束，不因训练困难取消 |
| 基础操作与基本职责优先 | 目标是参与游戏，枪法分数不足以代表会玩 | 首版战术单一、胜率可能不高 | 基础任务完成后再提高水平 |
| 示范学习 → 纠错 → PPO 对照/微调 | 先建立动作，再补自主运行偏差 | 需要数据质量工具和训练接口 | 若示范无收益，先检查标签和分布再换算法 |
| 小型视觉策略优先，规则只处理明确任务 | 控制链路简单、便于测试 | 复杂战术与长时规划能力有限 | 经失败分析证明需要更强规划时 |
| 实时运行和步进训练并存 | 同时保留可控实验与真实时间验收 | 需维护语义一致性和延迟差异 | 若跨模式偏差大，增加实时采样训练 |
| CPU/低配优化放在能力基线之后 | 先证明模型能完成任务 | 后期可能需要缩小模型、蒸馏或修改最低配置 | 原速基线成立，进入目标硬件验收时 |

依据详见[参考项目](reference-projects.md)；具体落地见[系统设计](system-design.md)。研究组合尚未通过完整实验，不能因每个组件有论文就认定组合一定成功。

## 2. 暂不作为首版默认的路线

| 路线 | 暂缓理由 | 保留的用途 |
|---|---|---|
| 每个动作调用通用大语言/视觉语言模型 | 需要额外验证时延、输出稳定性和成本 | 离线分析、数据标注、后期慢速规划 |
| 直接采用通用机器人 VLA 权重 | 身体、传感器、动作与训练分布不同 | 数据规范、适配与泛化研究 |
| 直接复用 MLMove 的输入和延迟结论 | 使用结构化状态，学习范围主要是移动 | 团队行为指标和规则分工 |
| 一开始完全从随机策略训练完整 5v5 | 回报稀疏、行为难定位、环境未完整 | 基础课程成立后逐步扩大强化学习 |
| 硬编码整条定时按键宏 | 起点或画面偏移后缺少恢复能力 | 控制链路测试，不能作为学习成功证据 |
| 先采集大量视频再定义动作协议 | 容易缺少输入标签或产生无法迁移的格式 | 先少量试采与回放，再规模化 |
| 先迁移整个训练框架 | 未确认瓶颈是否来自算法框架 | 现有引擎和传输优化仍不足时比较 Sample Factory 等 |

## 3. 尚未冻结的配置

| 问题 | 当前建议 | 冻结前需要的证据 |
|---|---|---|
| 首张地图 / 区域 | Lotus 的一小片可达区域 | 路线、碰撞、出生、目标位置检查 |
| 固定主武器 | 一把步枪，优先复用完整实现 | 开火、弹量、换弹、后坐力与事件正确 |
| 画面尺寸 | 可从 320×180 比较 | 目标可辨认性和处理开销 |
| 记忆结构 | 帧堆叠对照 + CNN/LSTM 候选 | 遮挡、方向、恢复任务中的实际提升 |
| 决策频率 | 20–30 Hz 起步，60 Hz 世界模拟 | 执行一致性、端到端延迟、任务成绩 |
| 小地图与环境音 | 可见 HUD 建立后，分别配置实验 | 输入语义、显示/声音时效、数据对齐 |
| 奖励权重 | 任务事件为主，有限进展为辅 | 与基线对照，投机行为检查 |
| 示范数量与比例 | 少量高质量试采，按失败补充 | 学习曲线和覆盖缺口 |
| 最低部署硬件 | 尚未指定具体 CPU/GPU | 后期游戏同负载实测，不仅看模型文件大小 |

## 4. 已修正的理解与优先级

- 早期只有短导航任务；现在把长期第一阶段明确为 1A 移动交战、1B 跟队守点、1C 基础回合。第一个里程碑不能被误称为已经会完整游戏。
- 24–100 GB 显存是训练预算，不是部署硬件假设。先训练能力、后优化轻量部署；此前“先完成 CPU 性能测试才能训练”的顺序不再作为前置条件。
- 不依赖队友语音沟通，不等于排除所有游戏环境音。首批视觉基线是简化实验选择，环境音仍可后续加入。
- 图形流畅、模拟 tick、策略更新频率和推理延迟分别统计。加插值不能补回没有发生的新决策。
- 历史射击误差图用于射后诊断，不是实时停止或精度恢复的真值信号。
- 已安装提示不自动提供安装位置；未知信息保持未知，不能从奖励或后台状态偷取。
- B 站元数据、简介和公开笔记不等于完整视频或评论。来源不足的内容保持待核查。

## 5. 失败时如何调整

动作没有正确执行，先修协议与环境；示范回放不一致，先修时间对齐；离线拟合好但闭环差，先补自主运行与恢复数据；单项会但组合失败，先检查任务转换与记忆；训练吞吐低，先检查渲染设备和图像传输；部署慢，先分解延迟再决定量化、裁剪或换模型。

改变网络规模或堆更多训练步数不应成为所有问题的默认处理。每次调整至少对应一种已观察失败，并保留旧配置和评估结果供比较。
