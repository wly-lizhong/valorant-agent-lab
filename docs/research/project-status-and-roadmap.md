# 目标、现状与路线图

更新：2026-11-25。状态：研究方向与实施计划；本次为文档发布。返回[研究目录](README.md)。

## 1. 产品目标

训练一个根据玩家可获得信息行动的 FPS 智能体：能连续移动、观察、对可见目标射击、换弹，并在有限地图中完成基本跟队和攻防职责。允许固定角色、固定主武器、固定路线和防守位置。先达到基本参与，再提高适应性和战术水平。

“像真人”的第一层含义是动作和任务连贯：不过度抖动、不长时间顶墙、不对空持续开枪、不在交战结束后停止行动、不把击杀当成唯一目的。不以职业枪法或高胜率作为首版前提，也不声称模拟器成绩等于真实客户端效果。

训练目标环境为 Ubuntu 22.04/24.04 + NVIDIA，显存预算按 24–100 GB 考虑；运行端未来可能只有 CPU 或低配 GPU。训练优先，量化、蒸馏与低配部署优化后置。游戏本身的渲染需求与模型推理需求分开评估。

### 环境自检与正式训练分别验收

现有 `configs/lotus_navigation.json` 中的短路线和青色立柱用于快速定位渲染、控制、重置、奖励或存档问题。这份配置继续保留为工程回归工具；其距离和可见标记不定义项目的能力目标。当前默认训练命令仍使用它，修改文档不会改变运行任务。

正式任务需另建配置、示范集和评估集。第一次模型交付以 1A 的移动交战闭环为准；第一阶段完整交付还包括 1B 跟队守点和 1C 基础爆破回合。分别报告环境正确性、模型能力和实时连续性，不用某一项通过替代其他项。

## 3. 第一阶段：固定套路的基础参战版

1A、1B、1C 均为待实现方案。先让基础动作能够连续组合，再加入队伍职责和回合规则；每一步都有独立场景和验收，暂不使用技能。

### 1A — 移动与交战

场景限制在 Lotus 一个含拐角和掩体的区域；固定一把步枪和角色外观。先用固定目标，再加入少量移动目标或弱对手。

完整闭环：从稍有变化的出生位置/朝向出发 → 沿已学路线前进 → 发现可见目标 → 停稳并射击 → 必要时换弹 → 目标离开或交战结束 → 继续到达终点。

正式场景默认关闭辅助路标和额外教学高亮，使用真实地图地标，以及事先公开的固定路线、目的地或任务 ID；玩家正常可见的 HUD 与角色轮廓按画面配置保留。任务上下文可以表达“去这个岗位”，不能传入当前角色世界坐标或隐藏敌人位置。需要辅助标记的诊断实验单独标注，不能混入无辅助条件的验收结果。

| 课程 | 场景设计 | 要观察到的行为 |
|---|---|---|
| 路线移动 | 含转弯与掩体的可达路线；小幅改变起点和朝向 | 根据画面修正方向、绕过障碍并到达，不依靠固定时长按键 |
| 停稳交战 | 从可见固定目标开始，再加移动目标或弱对手；混入无目标回合 | 观察、停止移动、瞄准、有效射击；目标消失后停止无依据的持续扫射 |
| 移动交战组合 | 路线上可能遇敌，也可能一路无敌；交战后仍有目的地 | 接敌时切换动作，交战结束后继续原任务，而不是击杀后立即结束回合 |
| 恢复与资源使用 | 走偏、暂时遮挡、低弹药、需要换弹和失败重置 | 能纠正位置、利用画面信息判断换弹，并恢复任务；失败有明确结束条件 |

1A 同步补齐可见的基础弹药、血量与换弹反馈；策略从画面获取这些信息，诊断接口里的真值仅用于奖励和统计。若首批固定靶没有反击，标为射击课程，加入有伤害的对手后再评价生存与受伤恢复。

奖励围绕有效任务进展、对敌有效命中/伤害和终点完成设计；不奖励按下开火、换弹或单纯移动的次数。成功要求完成整段任务，死亡和超时分别记录；空场景及停稳瞄准时的合理静止不能被一概处罚。权重留到基线实验确定，详细约束见[奖励与评估规范](data-training-evaluation.md)。

**交付**：可手动检查的场景、同步录制回放、单项及组合评估集、模型 checkpoint、原速成功与失败录像。

### 1B — 基础队伍参与

增加脚本队友与简单对手：攻方视觉跟随，不堵前进或后退通道；守方到预定岗位，观察入口，接敌后恢复职责。先固定跟随对象，再处理队友暂时离开画面和重新寻找。

不通过后台队友目标、未来路线或隐藏敌人位置直接指导策略。携包者身份需要可见标识或事先公开的任务约定。

**交付**：跟队、跟丢恢复、固定守点三组情境及分别统计的结果。

### 1C — 基础爆破回合

加入队伍、携包、安装、守包、回防、拆除、死亡和回合重置。先少量角色验证完整流程，再扩展为脚本队友/对手参与的简化 5v5；首期只训练目标智能体，不要求十个角色同时学习。

固定点位和路线减少规划难度。任务转换依赖玩家可见反馈：知道“已安装”不一定知道安装位置，未知时应获取信息或搜索。目标规则和时序须在目标环境中明确实现，不能由教程里的旧数值直接定案。

**交付**：完整回合回放，以及攻击、防守、交互完成和回合重置分项报告。

## 4. 开发工作包与依赖

| 工作包 | 具体内容 | 完成标志 | 依赖 |
|---|---|---|---|
| W1 场景与协议 | 锁定区域/武器、测量移动与枪械基线、细化视角动作、定义基础 HUD 和观察契约 | 场景可手动检查；参数、已知偏差、动作时间单位和数据版本有记录 | 现有环境 |
| W2 实时与录制 | 精确步进和实时模式共享动作语义；画面与已执行动作同步记录 | 连续运行，重置不残留输入，记录可回放 | W1 |
| W3 单项任务 | 无辅助路标的导航、停稳射击、换弹、空场景、恢复；基础 HUD、事件与奖励 | 人工和脚本验证任务判定；正式配置与自检配置分开，留出评估集可运行 | W1，可与 W2 部分并行 |
| W4 首批学习 | 小规模示范质量检查、BC、模型走偏后的纠错 | 模型产生可复现的基础行为，失败能归因 | W2、W3 |
| W5 组合与微调 | 导航交战切换、PPO 对照/微调、旧任务回归 | 完成 1A 的单项与组合门槛 | W4 |
| W6 队伍与回合 | 跟随、守点、目标交互和简单回合逻辑 | 完成 1B、1C；各状态有退出和恢复路径 | W5 |

首轮工程只做 W1—W3，交付可手动试玩、可重置、可同步录制并可独立评估的 1A 任务环境；首轮学习再做 W4—W5。先交可检查场景与少量试采数据，确认回放一致后再扩大示范和训练，避免录制大量旧协议数据后重做。

排期按产物推进。首次测得单环境吞吐、并发扩展和学习曲线后，再给训练时间预算；增加显存不必然按比例缩短训练时间。每一轮保存配置、数据版本、失败类别和最佳/最后 checkpoint，便于换服务器恢复。

### 参数核验前移到示范采集之前

地图外观还原度与操作机制还原度分开验收。先测量现有环境并建立版本化基线，不能把“沿用上游”作为机制正确的证据，也不能以“以后校准”为由忽略直接影响学习的错误。

| 时间点 | 必须完成的事情 | 放行条件 |
|---|---|---|
| W1—W3，正式采集前 | 记录 FOV、视角增益、移动速度、停止过程；检查停稳/移动时的射击精度、射速、弹量、换弹、后坐力及遮挡命中 | 人工/脚本测试能重复；影响任务判定和学习方向的错误先修复；未确认的官方差异列入清单 |
| W4—W5，学习期间 | 固定本轮物理、观察、动作和奖励版本；检查移动射击是否绕过精度惩罚、隔墙命中是否符合配置的穿透规则、按键频率是否改变物理结果 | 发现机制漏洞先修环境并复测；变更后明确旧示范和模型是否兼容，必要时重录或重训 |
| 后续迁移阶段 | 与目标客户端逐项对照并收敛参数差异，测试画面、HUD、地图版本和输入延迟 | 有同条件对比记录和任务回归，才评价迁移效果 |

首批可以在已记录偏差的模拟条件下建立能力基线，不要求先完成所有官方参数复刻；但停稳射击、弹药消耗、换弹和遮挡等任务成立所依赖的机制必须先验证。

## 5. 拟定验收门槛

这些是待基线测试后校准的工程目标，不是已测结果或论文承诺。

| 维度 | 初始门槛或报告要求 |
|---|---|
| 单项导航 / 简单射击 | 各至少 100 个留出回合，成功率目标 ≥90%；写清射距、目标大小、速度和时限 |
| 1A 组合任务 | 初始完成率目标 ≥80%，同时报告卡墙、空放、无效换弹和任务切换失败 |
| 稳定性 | 初次模型可先单种子；宣称方法稳定前再比较至少 3 个训练种子及不同测试起点 |
| 连续性 | 原速、不挑选的连续评估录像；报告长停顿、视角振荡和动作过期 |
| 实时性 | 候选 60 Hz 模拟、20–30 Hz 新策略更新；记录整条链路 p50/p95/p99 和超时率 |
| 信息一致性 | 策略输入断开隐藏状态；遮挡、空场景和安装位置未知情境不出现全知动作 |
| 回归 | 新任务训练后重跑旧任务，防止“学会交战但不会走路” |

后续可采用“模型前向 p95 ≤10 ms、画面形成到动作应用 p95 ≤50 ms”作为训练/演示设备上的候选预算。需在游戏与模型共同运行时实测；不把它们当低配 CPU 已能达到的保证。

## 6. 第一阶段之后

| 阶段 | 目标 | 扩展方式 |
|---|---|---|
| 第二阶段：同图稳健性 | 不依赖唯一出生点、目标位置和队友路线 | 多起点、多路线、不同目标行为、更多恢复情境 |
| 第三阶段：迁移与精细校准 | 在第一阶段已核验的机制基线上，缩小与目标客户端的差异 | 对比画面、HUD、FOV、移速、停止、后坐力、输入延迟；逐项扩大地图 |
| 第四阶段：部署 | 在目标 CPU/低配 GPU 上连续运行 | 导出一致性、量化/蒸馏、线程和图像管线优化，再做闭环回归 |
| 后续增强 | 提升信息与策略能力 | 环境音、更多武器、技能、经济与复杂配合按短板加入 |

真实客户端适配需要单独验证观察和控制接口、输入执行与任务规则，不能把模拟器世界坐标接口原样搬过去。部署适配不自动证明真实对局效果。

## 7. 开始 W1 时需锁定的配置

区域及路线、固定武器、目标类型与大小、分辨率、基础 HUD 样式及是否加入小地图、动作单位与频率、重置条件、数据切分策略。基础弹药与血量反馈纳入 1A；环境音频首批是否启用仍需单独决定，不依赖队友语音指挥是既定范围。

这些内容应成为版本化配置。具体样本数、奖励权重、并发数和训练步数在基线测试后定标，不从真人教程的分钟数推算。
