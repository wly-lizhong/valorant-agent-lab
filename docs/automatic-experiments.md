# 有限批次的自动训练与评估

`scripts/run_bc_experiments.py` 用普通 Python 子进程执行已经确定的实验。它不调用大语言模型，也不创建 Goal、定时唤醒或自动调参服务。训练过程中不需要 AI 反复读日志。

首轮配置在 `configs/bc-experiments-round01.json`：

| 候选 | 视觉特征 | 动作头 | 动作损失 |
|---|---|---|---|
| normalized | LayerNorm | Tanh | 原始分布 |
| balanced | LayerNorm | Tanh | 仅从训练集计算的有限平方根逆频率权重 |
| balanced-relu | LayerNorm | ReLU | 同上 |

三个候选使用同一数据、随机种子 42、batch 128、学习率 3e-4、60 epochs。每个候选依次运行：训练、best 的离线诊断、latest 的离线诊断、4 个 dev 路线场景、4 个 dev 射击场景。游戏评估使用 best；同时保留 latest 诊断，便于识别仅按验证 NLL 选出的模型是否忽略少数动作。

这是候选实验，不是证明已经学会游戏的正式验收。仅 dev 场景用于此流程，最终 test 场景不会打开；人类示范中的 train 和 validation 始终分开。

## 在 Linux 云端运行

从当前候选源码根目录执行。先加载既有 NVIDIA 图形环境；不要安装或更换系统驱动。源码与 `runs/gpu-display-*` 应在实例本地盘，输出目录可以放在持久盘；FUSE 持久盘不适合作为 Xauthority 运行目录。

```bash
python scripts/run_bc_experiments.py \
  --manifest configs/bc-experiments-round01.json \
  --data /path/to/demonstrations-v215 \
  --output /path/to/persistent/experiments-round01 \
  --device cuda --gpu-display
```

`--gpu-display` 为本次任务创建私有 NVIDIA X 显示，运行结束时只清理它自己的进程。已有桌面、VNC 和其他显示不动。指定 GPU 时使用 `--gpu N`；显存和利用率采样记录整张指定 GPU，不冒充本进程独占用量。

后台任务应通过 `bash scripts/run_bc_experiments.sh` 启动。如果实例使用另行准备的 NVIDIA 用户态图形库，
在后台启动脚本里明确设置 `VALORANT_LAB_GRAPHICS_ENV` 为该实例**已有且可信**的环境脚本绝对路径；
包装器会先加载它。Python 路径可用 `VALORANT_LAB_PYTHON` 指定。不要依赖 SSH 登录 shell 或旧 tmux
服务进程继承的 PATH。CUDA 能训练不代表系统 Xorg 能找到 NVIDIA 图形模块；先通过实际渲染预检。
缺少环境文件会直接退出，不下载或安装驱动。

长任务可由现有 `tmux` 会话启动。启动后检查 `state.json`、阶段日志与第一个检查点即可；结束当前聊天不会让 tmux 中的 Python 训练停止。报告写完本身不会唤醒 AI，之后再让助手分析汇总。

低配 Windows 可阅读报告；要在 CPU 上运行整条流程，先复制 manifest 并把 `training.precision` 改为 `fp32`，命令使用 `--device cpu` 且不传 `--gpu-display`。这不保证低配机器训练很快，Windows 仍主要用于本地采集。

## 上限与恢复

- 每个 manifest 最多 3 个不同候选；参数不会由脚本自行增加或搜索。
- 首轮累计子进程预算 1800 秒；每次训练最多 600 秒、离线诊断 180 秒、每门游戏评估 300 秒。
- 每个阶段最多 2 次尝试。失败或超时即停止整批，没有自动无限重试；检查原因后显式传 `--resume`。
- 超时或正常中断会关闭该阶段自己的进程组/进程树。Linux `SIGTERM` 会转成可清理的中断；`SIGKILL` 无法执行清理，如恢复时检测到原子进程仍存在，脚本拒绝并发重跑，需先检查该 PID。
- 完成阶段先核对产物 SHA-256，再跳过。源码、manifest、实际数据、依赖版本或运行设备改变时拒绝恢复，避免混合实验。
- 训练恢复使用同一工作目录里的完整 `resume.pt`；恢复前复制输入检查点到新 attempt 目录。模型、优化器、随机状态的恢复由 BC 实现负责。若在第一个恢复点前失败，不猜测重置状态，应保留旧目录并新建实验目录。
- 诊断、评估的每次尝试都有独立目录，失败日志和轨迹不会被后一次覆盖。最终成功结果指向最近完成的 attempt。

恢复命令与首次运行相同，追加 `--resume`。修改 epoch 数量属于另一份 manifest，不能在已有结果目录里悄悄追加。脚本不会自动升级环境、安装依赖、改正式部署或推送 GitHub。

## 看哪些文件

| 文件 | 内容 |
|---|---|
| `state.json` | 当前阶段、状态、累计时间、每次尝试的命令、PID、错误、完整日志路径及产物哈希 |
| `identity.json` | 冻结的配置、源码哈希、数据清单和依赖版本 |
| `summary.json` | 每个候选的训练/离线诊断/真实游戏结果及 GPU 汇总；每阶段更新 |
| `gpu.jsonl` | 普通线程采样的 GPU 利用率、显存、功耗和所属阶段 |
| `<候选>/training/` | `best.zip`、`latest.zip`、恢复点、元数据和逐 epoch 指标 |
| `<候选>/attempts/<阶段>/attempt-NNN/` | 日志；诊断报告、游戏报告、逐步轨迹、起点与终点图片 |

`summary.json` 统计实际发射子弹数、命中、击杀、成功率、动作分布、连续相同动作长度、视角极限和疑似卡墙窗口。开火按钮按下的帧数与实际子弹数分开；疑似卡墙定义为连续 40 步中超过 70% 请求移动，但离窗口起点的最大位移不足 0.5 米，它是诊断指标，不是改写游戏成功条件。

游戏采用 lockstep 评估。推理 p95 会保留，但它不是实时端到端流畅性认证。原始 `trace.jsonl`、`start.png`、`final.png` 保留；默认不逐帧保存 PNG，避免小持久盘被图片撑满。loss、GPU 占用或离线准确率都不能替代实际射击、命中与路线完成。

## 开局等待对照与双检查点评估

候选可选 `initial_idle_policy: "skip"`，默认 `"keep"`。skip 仅在训练采样索引中跳过每条训练示范
开头、第一次非空操作之前的连续全空动作。首次转向也算非空操作；之后的停稳、瞄准、等待和不开枪
全部保留。原始文件、四帧历史、验证集不变，类别权重仅由选中的训练标签计算。模型及运行报告记录
每条记录跳过的数量，恢复时不允许更换此选项。它是待实测的学习假设，不是已证明的改进。

评估可选 `checkpoints: ["best", "latest"]`。best 仍按原来的验证 NLL 选择，latest 是最后一轮；
两者在相同 dev 场景分别运行并保存报告，不事后把较好的某一个冒充预先选好的模型。省略该字段时
保留原来的 best 评估行为。`configs/bc-experiments-round03.json` 固定两种采样方式、每种 600 epochs、
batch 512、AMP，8 个 dev 种子 × 2 个原课程 × 2 个检查点 × 2 个候选，共 64 局。累计子进程上限
1800 秒；最终 test 种子不参与。GPU 预检、数据校验和本轮程序验证通过后才启动。

## 误标示范的排除

经确认需要排除的记录，保留原文件并移到数据目录内的 `.excluded/episode-.../`，另存
`exclusion.json` 说明原因和原文件哈希。训练加载和导出只读取数据根目录下的记录，因此不会使用
该子目录；重复导入相同记录时会校验原文件并跳过，同 ID 内容变化则报错，不会自动恢复训练资格。
已有实验使用冻结快照，排除操作不能撤销模型已经学过的数据。准备下一轮时按训练加载器实际选中的
记录生成新快照，并核对排除 ID 不在其中；不要把误标训练记录直接改成验证记录。

### 2026-11-27：过拟合与空间分辨率对照

round04 的最佳检查点在第 90 轮，600 轮末训练 loss 接近零，但验证 loss 约翻倍；原射击仍仅 1/8 成功。近距独立开发诊断中 best 为 2/8、latest 为 3/8，无人近距场景均 8/8 且没有误开枪，说明仍存在闭环停滞和泛化问题，不能用更长训练证明改善。

增加两个可选 BC 编码器：`normalized-dropout` 在特征层使用训练时 Dropout；`spatial-dropout` 保留 7×14 空间网格并使用同样的 Dropout。前者检验正则化，后者进一步检验原 3×5 池化是否损失瞄准位置细节。推理时 Dropout 关闭，旧模型结构保持兼容。新架构是待验证假设，不是已证实修复。

自动实验仍强制原路线与原射击评估，可额外添加 `close-engagement`、`close-clear`，后两者不能替代正式课程。round05 复用已校验的 round04 数据，比较两个新候选与保留的既有基线，固定 batch 512、600 轮和随机种子；另做有限 GPU 批量吞吐测试，为下一批提供依据，不为提高占用率改变本批比较条件。所有实验受本次 12 小时绝对截止和各阶段时限约束。

### 2026-11-28：在线学习退化与示范复习对照

round06 的 128 局开发评估已完成。原起点候选在 32,768 步时原射击为 3/8，继续到 65,536 步降为 0/8；近距候选末轮近距射击 5/8，但原射击仍为 0/8，不能推广为整体进步。人类示范验证集的开枪召回率从 BC 父模型的 0.48 降至原起点 PPO 中期的 0.36、末期的 0.24，打乱画面仍显著影响预测。这支持检查在线更新遗忘，不能归因于模型完全不看图。

### 2026-11-28：动作选择与停滞诊断

round08 完成 320 局。在同一 16 个开发种子上，100% 有敌训练的末期模型原射击从父模型 2/16 提升到 7/16，保留原有两个成功案例、另增加五个；但空路线开枪从 23 发增加到 116 发，近距成功从 7/16 降到 4/16，仍未达到验收。75% 有敌候选末期原射击只有 1/16。提高轮数或战斗比例并不能保证所有行为一起改善。

round09 冻结 round08 的 100% 有敌末期模型，比较原 mode 与温度 0.5、1.0 两项采样，每项用两个随机编号重复，四任务各 16 局；新增 256 局，并复用已经验证哈希的 64 局同模型 mode 对照。额外统计动作切换、移动切换、开枪切换、横向反转以及转向幅度，成功率提升若伴随明显抖动或误开枪增加，不能判为更好。它是锁步诊断，不是实时流畅性认证，也不是训练出新的模型；不挑选一次幸运采样作为结论。所有游戏规则和最终测试隔离保持不变。
